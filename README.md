## `> cat philosophy.txt`

```text
The model is not the system.

The system includes its inputs, validation, data, queues, retries, timeouts,
monitoring, security boundaries, and the clarity of its interface.

Good AI engineering makes all of that visible — and makes the failure modes
graceful when the world stops behaving like the demo.
```

```mermaid
flowchart LR
  A["Intent"] --> B["Design"] --> C["Build"] --> D["Measure"]
  D --> E["Learn"] --> F["Improve"] --> C
  D -. evidence .-> G["Reliable decision"]
  E -. tradeoffs .-> G
  F -. resilience .-> G

  classDef phase fill:#101C3B,stroke:#00D9FF,color:#FFFFFF;
  classDef result fill:#7C3AED,stroke:#00F5A0,color:#FFFFFF,stroke-width:2px;
  class A,B,C,D,E,F phase;
  class G result;
```

| Principle | Engineering consequence |
| --- | --- |
| **Verification > confidence** | Treat generated output as a hypothesis to test. |
| **Evidence > assumptions** | Retrieve, measure, and log the signals that matter. |
| **Systems > demos** | Design for retries, queues, failure recovery, and maintainability. |
| **Observability is product work** | Make state and behavior understandable in production. |
